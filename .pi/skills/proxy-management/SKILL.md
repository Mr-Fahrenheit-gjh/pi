# 本机代理分流管理

围绕**实际请求路径**处理问题：客户端 → macOS 系统代理或显式代理 → PandaFan 分流 → 出口。进入本机代理不等于经过境外节点；系统绕过也不能证明 TUN 层出口。

工作区根目录为本技能目录的 `../../..`。分流规则的唯一配置源是 [rules.yaml](../../../工具/代理分流管理/rules.yaml)，命令入口与修改副作用见 [工具 README](../../../工具/代理分流管理/README.md)。规则保存在那里，技能只保存流程。

## 1. 确定要影响的客户端

从用户提供的网站、故障和现有上下文确定目标：
- 网站卡顿或“是否走代理”：先只读诊断。
- “这个网站直连／走代理”：诊断后执行已授权的定向修改。
- 仅命令代理、环境变量或临时运行模式：读取 `~/.pi/agent/skills/proxy-env/SKILL.md`，沿现有工具操作，不修改系统代理。
- 重连后失效：重新检查实际生效设置，不把旧记录当现状。

只有目标、影响范围或必要授权确实不清楚时才问。**完成条件：**知道用户要查还是要改、目标网站，以及影响的是浏览器、命令还是特定应用。

## 2. 查路径，再解释快慢

涉及浏览器、系统代理或 PandaFan 时，读取 [系统路径排查](references/system-routing.md#只读诊断)，按需运行其中的检查。只有持续访问失败、异常登录或已有路径异常证据时才扩大网络排查；普通单页超时先直接重试。

采集系统代理与活动网络服务、目标域名的系统代理选择；若请求交给 PandaFan，再核实当前智能分流、规则及 TUN 状态。只读取必要字段，避免展示包含订阅、登录或节点凭据的完整配置。

有卡顿时，按需做有超时的直连／本机代理对照。网页首包、视频吞吐和实际播放分别描述，单次计时只能作线索。

**完成条件：**能区分“客户端是否交给本机代理”和“最终出口是否已证实”；未知项明确标注。不因端口监听、规则中出现 DIRECT 或一次测速就判定最终出口、卡顿原因。

## 3. 只改目标所需的一层

需要修改时读取 [定向修改与恢复](references/system-routing.md#定向修改与恢复)：
- 命令自动分流：修改唯一规则源并沿现有生成流程更新。
- 浏览器直连：保留原有系统例外，给活动服务补根域名与子域名例外；网站依赖域名来自实际请求或已核实规则。
- 应用显式代理／TUN 仍接管：处理实际接管层，不能把系统绕过当作已解决；没有受支持入口或缺授权时报告具体阻碍。
- 强制走代理：先区分“交给 PandaFan”和“必须用境外出口”；现有 NO_PROXY 工具不支持可靠的 always_proxy 例外。

定向网站授权只覆盖对应分流设置；全局代理切换、sudo、shell 修改、安装升级、launchctl 与正式服务重启按工作区确认规则处理。使用现有受支持入口；历史 Clash 配置只供查阅。

**完成条件：**修改范围与授权一致，原配置可恢复，其他网站及已有例外保留。遇到权限失败停在该步骤，不自动提权或重启服务。

## 4. 在实际生效层验收

- 系统绕过：回读服务例外，并运行 `python3 scripts/system-route.py <目标URL> <相关资源URL> <原本走代理的对照URL>`。目标返回直连，对照保持原代理行为。
- 命令规则：运行 `pi-route check`，核对生成物与必要后台副本；磁盘一致与运行进程已加载分别记录。
- 修改 PandaFan 分流时：核对运行状态或连接证据。只有磁盘规则时，保留“最终出口未验证”。
- 用户关心卡顿：报告已经测试的性能指标。未测试真实播放，就写“实际播放未验证”，不把配置成功写成不卡顿。

工具返回错误时修复本任务引起的问题或报告剩余阻碍；未完成项目保持未完成。提交前检查差异，只提交本任务相关文件。

**完成条件：**给出实际修改、验证命令与结果、必要刷新／重连动作及提交标识；区分已生效、仅磁盘更新和未验证，不为生效擅自重启。

技能本身的修改按 [写作依据与场景验收](evals/scenarios.md) 检查；不因此改网络设置、运行整套应用测试或重启服务。
