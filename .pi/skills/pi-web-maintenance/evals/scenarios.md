# 技能维护：场景验收

修改本技能时按本表审阅；发现真实反例就补对应分支，不为每条规则堆流水账。

## 分流

| 输入 | 应走 | 可以判定完成 | 要拦住 |
| --- | --- | --- | --- |
| “把按钮间距调一下”，未批准发布 | A 源码档：局部样式 + 受影响检查 | 说明源码已验证、未构建 | 默认 tsc/lint/全套测试/多视口/构建 |
| “想用英文”，设置已有语言切换 | 先跑 `--features`，告知现有入口 | 用户能在设置里切换 | 新建语言迁移或全站扫描 |
| 需要看真实排版的小改动 | B 预览档：单个 e2e 套件或 dev server | 受影响行为通过 | 生产构建 + 全套浏览器矩阵 |
| 用户明确要求上线 | C 发布档：一次构建 + `--evidence` + 守卫 | 30141 正式验收通过 | 每个小改动各发布一次 |
| 同一天多个待上线小改动 | 合并到一次发布 | 一次构建、一次守卫 | 逐条 prepare/apply |
| 已有 e2e 套件覆盖需求 | 复用该套件 | 同一构建上通过 | 任务目录另写 `verify.mjs` |
| 改一个词条 | 词条/占位符核对或相关单测 | 三语言齐全 | 全组件测试、构建、浏览器套餐 |

## 发布与证据

| 输入 | 必须发生 | 必须不发生 |
| --- | --- | --- |
| 需要同构建证据 | `flow.py --evidence` 生成三件并核对绑定 | 手写/复制 `smoke-result.json`，累积旧字段 |
| `--evidence` 某步失败 | 读该步日志，修原因后重跑该步 | 重跑已通过的步骤或重建未变产品 |
| 证据 BUILD_ID 或 packageRoot 不匹配 | 重新生成 | 改旧报告字段冒充新构建 |
| 真实历史父会话 pending | GET 前阻断，报告阻碍 | 改写恢复状态、禁用扩展、新造模型调用 |
| 守卫已 deployed 且身份一致 | 核对身份后收尾 | 再 prepare/apply 或重启一次 |
| apply 期间主会话中断 | 先查原任务和 state | 把连接中断误报为发布失败 |
| 只有当前会话获准中断 | 一次性 `--restart-session <UUID>` | 放宽其他会话/PTY 保护 |
| 发布锁被占用 | 报告拥有者/计划，等待或同一计划续跑 | 删锁、覆盖计划 |

## 记录

| 输入 | 必须发生 | 必须不发生 |
| --- | --- | --- |
| 阶段交付 | 任务 README ≤15 行 + 机器生成证据 | 抄 SHA、截图清单、逐项断言 |
| 仅文档或技能修改 | diff + 链接/规则一致性 | 应用测试、SDK 加载、构建、浏览器 |
| 修改 flow/守卫脚本 | 对应 Python 单元测试 + `--features`/`--evidence --dry-run` | 借脚本修改再跑应用或发布 |
| 独立审查 | 只在 API/存储/权限/恢复/发布器改动时开 | 默认派发、审查后重跑全套 |
| 发现与目标无关的旧问题 | 简短指出，留出主线 | 顺手修复并扩大验收 |

## 本技能的写作依据

参考 Matt Pocock 的 `writing-for-agents`（提交 `49dd158d1076134a641b33efb035946536778336`）的增量交付写法：主文件按步骤组织，每步有完成条件；细节放条件引用的 references；不把禁令和事故流水堆进主流程。实际行为以当前 Pi 加载器和发布守卫为准。

修改技能本身时的检查：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s .pi/skills/pi-web-maintenance/tests -v
python3 .pi/skills/pi-web-maintenance/scripts/snapshot.py
node --test .pi/skills/pi-web-maintenance/tests/validate-skills.mjs
```

这些只证明文档与工具结构可用，不证明未来每个模型都会遵循；出现反例时记录具体分支再改。
