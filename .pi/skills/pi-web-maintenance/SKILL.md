# Pi Web 维护：先找现成能力，按三档交付

本技能是修改、内核/Web 升级、候选验证、正式发布与恢复的统一入口。保留主题、字体、布局、Ghostty 和父子代理等现有本地合同。版本/依赖、全局安装与正式重启仍需当轮授权；脚本有选项不等于获准。

默认只做到“源码已验证”并按 `<工作区>/工具/pi-web维护/待上线/README.md` 登记。只有当前对话明确要求上线，才进入发布档。

## 0. 每个需求先回答三个问题

1. **现成能力够吗？** 运行 `python3 flow.py --features`（维护目录）。一次列出设置分区、界面语言、API 路由组、已有 e2e 套件和已有本地定制。
   - 设置或原生入口已满足 → 直接告诉用户怎么操作，不改代码、不构建、不登记。
   - 已有 e2e 套件覆盖 → 复用它，不另写验收脚本。
2. **必须改代码吗？** 只改最小文件。新断言加到 `<源码>/e2e/<feature>.mjs`，不在任务目录新建 `verify.mjs`。新发现的问题只有阻止本次目标或由本次引入才修。
3. **要发布吗？** 没有当轮授权就停在源码档；不构建候选、不复制发布包、不写“候选通过”。

除纯文档/技能修改外，先跑一次 `--features` 再决定是否开发。实施前只需要一句话：缺口、完成条件、最小验证。小改动不写计划文档。

## 1. 三档路径，选一档并停在该档

| 档 | 触发 | 最小动作 | 完成条件 |
| --- | --- | --- | --- |
| A 源码级 | 文案、样式、局部逻辑，未要求上线 | 改最小代码 + 相关单测或 `lsp_diagnostics`；要看效果才起 dev server | 定向检查通过，登记“源码已验证，未构建” |
| B 预览级 | 需要真实页面确认排版/交互 | `flow.py --validate --profile ui --test <文件>`；交互无单测覆盖时才加一个浏览器套件 | 受影响行为在候选/预览上通过；不跑无关套件 |
| C 发布级 | 当轮明确要求上线 | 复用有效候选，否则一次生产构建 → `flow.py --evidence` → 唯一守卫 prepare/apply | 正式 30141 验收通过；失败就报一个具体阻碍 |

- 默认走 A。不要因为“反正要验证”把 A 升级成 B 或 C。
- B 只跑能发现本次错误的检查；能用 dev server 就不做生产构建。
- C 默认批量：同一次发布带上待上线清单里互相兼容的条目，不为每个小改动各构建、各发布一次。
- 每档通过即收尾，不追加“顺手再验一次”。

## 存储边界（复制、构建之前执行）

- 在新建/复制整包候选之前先运行：`python3 <维护目录>/storage_policy.py --before-copy <目标候选路径>`。空间不足先清理，不先复制再想办法；候选尽量复用，不为每轮验证新建一份。
- 正式上线验收成功、发布状态与正式 BUILD_ID 一致后，自动删除已识别的 Web 回退包，不再保留最近两份；未成功或仍在发布/恢复时保留最近两份及当前回退。当前配置候选、未上线登记和运行进程/验证锁引用的包不删除；候选旁的证据保留，未知包不盲删，其他工具备份不受此策略影响。
- `flow.py --validate`、发布 prepare 和成功 apply 已接入轮转。复制/构建要求至少 8 GiB 可用（3 GiB 工作量 + 5 GiB 底线）；候选整包超过 3 份会阻止继续增长，先核实保护项或未知项。保留项不因配额被强删。
- 手动检查：`python3 <维护目录>/storage_policy.py`；确认清理：追加 `--apply`。不清理其他应用、会话、凭据或源码工作树，不用这一步重启正式服务。

## 2. 发布门禁是代码事实

- 守卫要求同一 BUILD_ID 的三件证据：`smoke-result.json`、`<源码>/test-results/quiet-tools/result.json`、`runtime-probe-result.json`（`launchd: true`）。它们都由脚本生成：
  ```sh
  python3 flow.py --evidence --dry-run   # 只读：身份 + 现有证据是否匹配
  python3 flow.py --evidence             # 依次生成三件证据，再报 releaseReady
  ```
  成功时只读最后一段 JSON；哪一步失败才去看那一步的日志。不手写、不复制、不累积旧字段。
- 发布只走 `upgrade_when_idle.py --prepare <真实历史会话UUID>`，再用后台任务跑 `--apply`。不手工换 `.next`，不 `launchctl kickstart`，不全局安装官方包。
- 正式验收由守卫执行：30141 + BUILD_ID + 真实孩子。守卫通过后只核对身份，不从外部重跑同轮全套。
- 涉及重启当前会话时，才追加一次性的 `--restart-session <当前UUID>`；其他会话与 PTY 保护不变。

## 3. 不要做的事

- 不把候选侧二十多项界面断言在正式路径再跑一遍；正式侧只补环境相关项（安装路径、launchd、真实历史）。
- 不为小改动写独立审查、全套浏览器矩阵、多个分辨率/主题/语言。审查只在 API/存储/权限/恢复/发布器改动时开；审查后只复验受影响项。
- 不在任务目录新建浏览器脚本，不为了“统一入口”套用完整验证套餐。
- 没有发布授权不构建、不启动正式宿主探针、不把登记条目当上线授权。
- 构建或测试只在源码收敛后跑一次；调一处就重跑全套是浪费。

## 4. 记录与交付

- 任务 README 不超过 15 行：当前阶段、源码提交、候选/BUILD_ID（如有）、实际执行的验证与结果、未验证项、回退位置。
- 证据用机器生成的文件；不在 README 里抄 SHA、截图清单和逐项断言。
- 只提交本轮相关文件；运行 JSON、截图、日志不入库。
- 交付说清楚：已完成/停在哪档/一个具体阻碍。
