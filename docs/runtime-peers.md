# Pi 与 Feynman 的独立会话

Pi Web 在同一个界面中提供两个运行时。点击侧栏的名称打开切换菜单，选择 `Pi Web` 或 `Feynman`。菜单关闭时不增加按钮或箭头。

## 两个运行时的边界

`/` 使用原 Pi 后端。`/feynman` 使用独立 Feynman CLI 的 JSONL RPC，不把 Feynman 安装进 Pi，也不共用进程内 SDK 实例。两个标签页可以分别打开这两个入口。

Feynman 的配置、模型授权和会话保留在自己的安装目录。`PI_WEB_FEYNMAN_ROOT` 指定该目录，默认值是 `~/Documents/pi/工具/科研idea流水线/feynman独立环境`。安装缺失时服务报错，不自动安装或升级。现有安装固定使用 `openai-codex/gpt-6.1-sol`、`medium` 和普通服务层级。

客户端在发出请求时确定运行时。Feynman 的会话请求进入 `/api/runtime/feynman/`，不会回落到 Pi 的会话或设置接口。文件浏览、Finder 定位、浏览器和终端仍是宿主工具，不是另一份会话存储。

会话列表、置顶、归档、项目排序和上次打开位置分开保存。页面切换只断开网页事件连接，不停止后台任务。阅读 Feynman 历史不启动其内核。恢复对话时，Web 持有该会话的写入锁；发现未由 Web 管理的独立 Feynman CLI 时拒绝接管。

Feynman 的运行任务、启动事务及排队磁盘操作均参与宿主重启保护，不能因 Pi 当前空闲而中断研究。重启排空期间拒绝新任务和写操作，状态查询与中止仍可用；升级守卫也读取独立运行时的忙态。

Feynman 暂不支持通过网页修改模型默认值、插件、MCP 或工具预设。对应接口返回 `runtime_unsupported`，不会修改 Pi。显式只读工具预设在启动前拒绝，不能把未生效的工具限制当作只读保障。

## 按需协作

两个运行时提供 `peer_agent` 工具。`/peer-agent` 只显示另一方的入口，不启动模型或派发任务。

| action | 行为 |
| --- | --- |
| `locate` | 返回另一运行时的安装和网页入口 |
| `list` | 按 `query` 搜索对话，用 `before` 分页 |
| `read` | 按 `sessionId` 读取当前分支的历史，用 `before` 读较早内容 |
| `artifacts` | 列出成果目录，或按 `path` 读取成果文本 |
| `status` | 返回目标对话的运行状态和入口 |
| `send` | 向指定对话发送消息，或在明确的 `cwd` 中新建任务 |

历史和成果全局按需查阅，不自动合并上下文。成果接口排除隐藏配置、已知凭据名称和符号链接。Feynman 的公开归档 `研究成果/` 也可查阅。配置隔离不是操作系统沙箱，文件接口也不承诺识别任意命名的秘密。

发送前，来源对话显示目标和消息的确认框。宿主授权只使用一次，绑定来源会话、用户轮次、目标和完整消息，五分钟后失效。Feynman 子进程不能通过自己的桥接 token 批准发送，宿主必须收到网页对匹配确认框的肯定响应。

转交的消息标注来源会话。转交消息本身不授权再次派发，因此不会自动互聊。运行中的目标默认把消息排队，只有明确选择 `steer` 才发引导。接收收据不代表工作完成，调用方还要用历史和成果核对结果。

## 验证入口

离线协议、隔离和授权测试：

```sh
node --test lib/runtime-client.test.mjs lib/feynman-rpc.test.mjs lib/runtime-peer.test.mjs
```

真实独立 CLI、扩展加载和反向桥接检查：

```sh
node e2e/feynman-runtime.mjs
```

第二条命令只查询状态并调用已确认加载的本地 `/peer-agent` 命令，不调用模型。它关闭自己的进程并清理临时工作区和测试会话。正式发布仍须走工作区的统一维护入口。
