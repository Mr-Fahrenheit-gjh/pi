# Local content-first workspace contract

This is the local composition contract layered over the upstream sidebar/session notes. Preserve the selected theme, message-body/code font preferences and official multicolour `public/icons/pi-mark.svg`. User-requested global UI reference faces are served locally under independent aliases; see `../interface-fonts.md` for official provenance, actual variable axes, copyright/distribution boundary and isolation from the existing message-body family.

## Layout
- Desktop left/right toggles stay at fixed viewport coordinates. The centre topbar has no surface or layout height and cannot intercept conversation pointers; the corner icons stay transparent. Hover previews use independent ephemeral state, never persisted open state; click pins/unpins. Both entry and exit stay outside flex layout until width reaches zero. Both hover previews and pinned panels use solid theme surfaces; do not restore transparency or gradient paint. Touch uses click only. Keep the right toggle outside the full-width panel\'s inert centre and reserve its area in both side-panel headers.
- The stacked sidebar has a serif Pi Web brand, a real search field and a full-width New row, regular system sans-serif navigation, a lighter theme-derived surface, and equal Settings/Restart footer actions. Use the same UI font for file names, project/Git names, menus, tasks, agent picker, working label and composer placeholders; preserve answer/code/brand fonts. Project groups have decorative folder icons; conversation rows offer direct pin/unpin using existing persistent family pins. Archive entry defaults hidden, with a browser-persisted Settings switch; archive storage is unchanged. The files-tab variant retains its functional tab controls.
- No chat title/session-actions menu or top-level robot button. Per-message accounting disclosures are absent for text and tool-only replies. Context usage is a read-only percentage ring, not an inspector opener.
- A reply composer has a compact 54px desktop text-entry surface and a separate toolbar below. The plus opens a native modal with a large file drop target and a file chooser, using the existing private attachment callbacks. The upload modal intentionally uses the reference's English copy and regular authentic Anthropic Sans UI face independent of page locale; limits remain accessible without an extra visible footer. Attachment image cards sit above the draft inside the rounded surface. Reply upload/model/settings/context/stop stay below and outside that surface; the icon-only send uses a return arrow inside the entry. Compact quoted composers retain sending.
- The new-session page centres the existing Pi logo with the browser-local English greeting Morning / Afternoon / Evening, Mr.Fahrenheit (boundaries 12:00 and 18:00; refresh while open). Use the authentic reference serif at its light 300 weight and a subtle theme-derived composer shadow. Its taller card says How can I help you today?, with upload and send along the inside bottom edge; the existing project/worktree picker and actual model/settings sit together below. Do not add fake voice controls or replace the active model with reference branding. Reply / Steer / Queue remain capitalized English placeholders in existing conversations.
- Completed process disclosures are absent by default; running disclosures remain expandable and explicit search reveal can expose retained historical process. Do not delete stored records or blocking input/permission UI.
- The minimap reserves no permanent column. Rail/lock/preview appear only on hover or keyboard focus, with a compact scrollable preview, normal-weight text and theme-derived colours. Leave the real scrollbar usable.
- ChatWindow does not mount the bottom extension status/widget shelf. This is a presentation decision only: keep extension state/protocol and blocking permission/input/custom UI functional.

## Answer surfaces
- Assistant heading sizes and paragraph spacing scale with the user's body size. Keep the existing emphasis weight and code font. User bubbles, file previews and tool output retain their own spacing.
- Assistant answers are unframed: no reply bubble, border, background or added padding. Preserve the existing user-message bubble, model icon/name, original block indices, streaming, answer/code fonts, alerts and written files. Long code/tables scroll inside their existing wrappers; compact screens must not overflow.
- Footer stays quiet until hover/keyboard focus (always usable on touch). Show copy plus a positive t/s value only when supported: live estimates use observed token growth; completed averages use output tokens divided by SDK-recorded request duration, including waiting. No timestamp-difference speed guesses, empty zero badges or added cost panels.

## Interface language
- The local interface defaults to English, including legacy browser preferences via a one-time locale-only migration. Later explicit language choices remain supported. Use Document, Pinned, New, Tasks and Sub-agents for English navigation.
- Translate system actions, loading/status text and accessibility labels through i18n; keep document names/content, conversation titles/messages, todo subjects/descriptions, agent task summaries and raw transcript/tool output unchanged. Never achieve English chrome by rewriting stored content.

## Right workspace
- Permanent Tasks, Sub-agents and Outputs tabs share the existing file/terminal workspace. They cannot be closed like documents. Mount their viewers only while the panel is open or previewed.
- AgentWorkspace selection is local and read-only. Use a width-bounded custom dropdown, short display summaries, status and exact run/step IDs. Identical display summaries may group records visually, never merge their identities; unknown revival scaffolding must not imply common lineage. Keep keyboard navigation, Escape, outside dismiss and per-record access. Native conversations use SubagentViewer; package children use PackageSubagentChat. Never call a main-session selection handler, start an agent or redirect the composer from that picker.
- GET `/api/sessions/[id]/todos` reads the existing live manager or the saved current branch, never starts a wrapper or calls `todo`. The `rpiv-todo-state` custom snapshot is authoritative over legacy `todo` result details, including a cleared list. Hide deleted tasks, preserve pending/in-progress/completed and poll only the visible mounted view. These are the same tasks used by the tool, not a second task database.

## Search and conversation files
- Cmd/Ctrl+K conversation results reuse the sidebar's live running/awaiting-input sets and browser-local unread set through AppShell, without extra polling or storage. The right metadata slot uses the same icons and translated labels, with awaiting input taking precedence over running, then unread. Idle conversations, commands and file results have no activity icon; opening the menu alone never marks a conversation read.
- The sidebar search row contains only its search icon and editable input, with no visible Cmd/Ctrl+K button. Keep Cmd/Ctrl+K opening the quick-actions dialog through the global keyboard shortcut. Keep matching commands first, in stable order: new conversation, project terminal, conversation files, Rename this conversation, Fork this conversation, open its working folder in Finder. Recent conversations and actual conversation-body/file matches follow, with previews and exact message targets. Reuse the existing session-content search and guarded file-index endpoints, with debounced, abortable, query/cwd-bound results. Reuse the sidebar controller's disk-only Fork and existing loopback file-manager action, using the clicked conversation ID/cwd, not a different selected file-browser folder. Rename opens the sidebar's existing inline editor for the current saved native conversation (not a folded read-only subagent), clearing sidebar search and revealing the correct main/pinned/archive row without changing its archive or pin status. Enter/blur commits and Escape cancels through the existing rename flow. Fork uses the existing per-session deduplication, transient refusal and navigation-race handling; expose it only for saved native Pi sessions. Finder errors use the existing toast/body handling and reveal the sidebar on failure. Do not restore focus/sidebar/pin placeholders or add a long-conversation navigator.
- The IME, terminal and existing modal dialogs keep their shortcuts. Escape closes only the top modal and returns focus without stopping an agent; selection actions run after modal cleanup. Do not send model prompts from search.
- Outputs is a simple automatic file list, not a pin manager. GET `/api/sessions/[id]/outputs` reads the current/selected branch, including pre-compaction history, without starting an agent. Include successful write/edit paths (also SDK-recorded nested calls) and explicit assistant delivery links; deduplicate with the latest reference first. Ignore read tools, user mentions, shell/stdout guesses, codemode store, arbitrary MCP text and full-output logs. Unreported shell-generated files and omitted/truncated nested arguments cannot be inferred; links are conversation file references, not proof of creation.
- Render file names and paths, with one-click FileViewer opening and the exact source session ID. Absolute paths outside cwd retain the existing session-reference/root/symlink checks; listing never grants file access. Do not scan directories, copy files, launch applications or consult project git state to infer ownership. A deleted or inaccessible file remains subject to the viewer's existing error handling.
- Only the visible mounted Outputs view fetches. Reuse the existing tool/run/focus refresh key, plus explicit refresh; no background polling or localStorage pins. During an active run, follow the manager's current leaf rather than freezing at the chat's earlier history snapshot. Abort superseded requests and isolate runtime/session/cwd/leaf scopes so stale responses never expose another conversation. Bound the response to the latest 500 paths and visibly disclose truncation.

## Chat attachments versus project uploads
- Manual `@` selection inserts the existing path; it never uploads or copies.
- Composer uploads/drops use POST `/api/chat-attachments`, storing non-image files under the agent's private `chat-attachments/<sha256>/<filename>` and inserting absolute references. Same content/name reuses its file; changed content never overwrites an earlier reference. Images retain their inline prompt path.
- Browser file upload cannot recover an original absolute local path; it must save a server-side attachment. Never claim this is an original-file link. The attachment store is not the session cwd, and composer uploads must not refresh/write the project explorer.
- Enforce bounded multipart input, 25MB/file and 100MB/selection, safe names, private file permissions and symlink refusal; clean only files/directories created by a failed call. The file explorer's explicit Upload action keeps its existing project-upload semantics.

## Pending release handoff
- The footer adds only the localized Pending releases label and its count beside the unchanged Settings/Restart actions. An independent desktop dialog shares Settings' shell, theme/font, focus and Escape tools, with pending/history views, evidence disclosures and copy-only handoff. Never fold it into Settings or Plugins.
- The shared registry covers completed, verified Pi Web/extension/memory/config work only. The default directory and CLI protocol live in [pending-releases.md](../pending-releases.md); `PI_PENDING_RELEASE_DIR` is a server/CLI environment override, never a request parameter.
- One UUID JSON per item; strict shared schema, no symlinks, per-ID cross-process lock, expected revision, exclusive create and atomic update. GET `/api/pending-releases` is read-only and no-store. Invalid items warn, directory failures are unavailable, and history does not count as pending. References are text only, never read from their target files.
- No automatic messages, main-Agent calls, release commands or service restart. Writers register only after completion/verification, then stop. Real registration and deployment require the operator's scoped authority. Never store credentials or real memory contents.

## Service restart
- ServiceRestartButton requires a confirmation dialog, waits for a changed server epoch and never resends an ambiguous POST. Manual AbortController/timeouts support Safari 16.2.
- POST `/api/service/restart` is only for same-origin loopback requests on 30141, the installed package cwd and the matching `cn.pi.web` launchd PID. Candidate/development instances reject it. No remote targets, arbitrary commands or force-busy overrides.
- Block running sessions, command admission/mutation waits, compaction, session creation, real extension work and live PTYs. Idle selected-browser leases are not work. Draining rejects new work and rechecks after asynchronous admission waits; Stop/control responses remain available.
- Implementation/testing does not authorize actually restarting the formal service. Unit/VM tests never run launchctl; candidate tests reject restart. A real restart still requires explicit operator confirmation and separate live verification.

## Motion and file rows
- Micro feedback uses the shared 110ms workspace token; the quick-actions surface uses one 160ms opacity/small-translation entrance. Keep focus-visible feedback and selected theme/fonts; no looping decoration or transcript animation. Panel transitions share the workspace easing curve without extending the desktop's 200ms exit contract. Reduced motion disables panel, backdrop, composer and file-chevron transitions, including preview and inline-style overrides.
- File rows share 28px height and 6px corners. Preserve indentation, path tooltips, Git status, hover actions and folder expansion. Stacked file-header spacing does not change the files-tab layout or session navigation.

## Verification
Use related component/restart/attachment/todo tests, typecheck/lint, then isolated headless checks: `e2e/workspace-design.mjs`, `e2e/ui-polish.mjs`, `e2e/chat-attachments.mjs`. `e2e/reading-polish.mjs` adds heading, file-row, pin, keyboard and reduced-motion checks after the workspace suite on the same isolated page. `runWorkflowPolishChecks` in `e2e/workspace-refinement.mjs` is the focused A+C/quick-actions check, using `prepareWorkspaceFixture(agentDir, { polishSibling: true })`, a synthetic second conversation and intercepted model commands. Synthetic fixtures and candidate success are not production deployment evidence. Keep `local-customizations.json` markers aligned with this contract rather than restoring removed UI during migration.
