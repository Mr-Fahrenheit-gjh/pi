# Local content-first workspace contract

This is the local composition contract layered over the upstream sidebar/session notes. Preserve the selected theme, message-body/code font preferences and official multicolour `public/icons/pi-mark.svg`. User-requested global UI reference faces are served locally under independent aliases; see `../interface-fonts.md` for official provenance, actual variable axes, copyright/distribution boundary and isolation from the existing message-body family.

## Layout
- Desktop left/right toggles stay at fixed viewport coordinates. The centre topbar has no surface or layout height and cannot intercept conversation pointers; the corner icons stay transparent. Hover previews use independent ephemeral state, never persisted open state; click pins/unpins. Both entry and exit stay outside flex layout until width reaches zero. Both hover previews and pinned panels use solid theme surfaces; do not restore transparency or gradient paint. Touch uses click only. Keep the right toggle outside the full-width panel\'s inert centre and reserve its area in both side-panel headers.
- The stacked sidebar has a serif Pi Web brand, New then Search as equal unframed navigation rows, and one labelled Settings footer action. Search opens the existing Cmd/Ctrl+J chat-search dialog, not a second input. New/Search live inside the main tree's scroll surface, not in a fixed header; brand and Settings remain fixed. A measured preamble offsets virtual-window/reveal coordinates and drag auto-scroll extent, while row/drag hit coordinates remain inner-local. Navigation uses the local Claude Interface Sans face with explicit PingFang SC/Microsoft YaHei CJK fallback: 14px/21px navigation, project names and conversation titles; 12px/20px sentence-case section labels; 32px desktop content/action rows and 28px section rows. Mobile retains 44px touch rows. Matched 20px stroke icons and a shared text column align navigation/projects with nested conversations. Pending-release polling/dialog and the restart control are not mounted in AppShell; backend maintenance APIs, scripts and records are retained. Use the same UI font for file names, project/Git names, menus, tasks, agent picker, working label and composer placeholders; preserve answer/code/brand fonts. Project groups have decorative layered-container icons and trailing collapse chevrons; conversation rows offer direct pin/unpin using existing persistent family pins. Archive entry defaults hidden, with a browser-persisted Settings switch; archive storage is unchanged. The files-tab variant retains its functional tab controls. Both file layouts keep the terminal and file manager direct; Git changes live in More file actions with their count/toggle, and a Finder failure still reveals a folded files section.
- No chat title/session-actions menu or top-level robot button. Per-message accounting disclosures are absent for text and tool-only replies. Context usage is a read-only percentage ring, not an inspector opener.
- A reply composer has a compact 54px desktop text-entry surface and a separate toolbar below. The plus opens a native modal with a large file drop target and a file chooser, using the existing private attachment callbacks. The upload modal intentionally uses the reference's English copy and regular authentic Anthropic Sans UI face independent of page locale; limits remain accessible without an extra visible footer. Attachment image cards sit above the draft inside the rounded surface. Reply upload/model/settings/context/stop stay below and outside that surface; the icon-only send uses a return arrow inside the entry. Compact quoted composers retain sending.
- On desktop, entering a conversation focuses the main composer after mount/draft restoration; returning to the window/tab restores it only when focus is idle. Mouse session/New navigation may hand off focus, but keyboard navigation, other controls/editors/terminals, selected message text, visible dialogs/menus and hidden/inert composers retain ownership. Do not refocus on streamed updates, move the caret, scroll the page or open a touch keyboard automatically; compact quote composers keep their explicit focus flow.
- The new-session page centres the existing Pi logo with a short English greeting ending in Mr.Fahrenheit, randomly selected once per welcome-page visit from eight variants. The time-based variant uses browser-local Morning / Afternoon / Evening (boundaries 12:00 and 18:00). Remember the previous choice in browser storage to avoid consecutive repeats when available; never rotate while the page stays open or on window focus. Use the authentic reference serif at its light 300 weight and a subtle theme-derived composer shadow. Its taller card says How can I help you today?, with upload and send along the inside bottom edge; the existing project/worktree picker and actual model/settings sit together below. Do not add fake voice controls or replace the active model with reference branding. Reply / Steer / Queue remain capitalized English placeholders in existing conversations.
- Completed process disclosures are absent by default; running disclosures remain expandable and explicit search reveal can expose retained historical process. Do not delete stored records or blocking input/permission UI.
- The minimap reserves no permanent column. Rail/lock/preview appear only on hover or keyboard focus, with a compact scrollable preview, normal-weight text and theme-derived colours. Leave the real scrollbar usable.
- ChatWindow does not mount the bottom extension status/widget shelf. This is a presentation decision only: keep extension state/protocol and blocking permission/input/custom UI functional.

## Answer surfaces
- Assistant heading sizes and paragraph spacing scale with the user's body size. Keep the existing emphasis weight and code font. User bubbles, file previews and tool output retain their own spacing.
- Live assistant prose paragraphs/headings enter once with a 180ms opacity-only fade. Same-paragraph deltas do not restart it or delay output; history, complex code/math/table blocks and reduced-motion users have no prose entry animation. Preserve Markdown DOM structure and stable keys.
- Assistant answers are unframed: no reply bubble, border, background or added padding. Preserve the existing user-message bubble, model icon/name, original block indices, streaming, answer/code fonts, alerts and written files. Long code/tables scroll inside their existing wrappers; compact screens must not overflow.
- Footer stays quiet until hover/keyboard focus (always usable on touch). Show copy plus a positive t/s value only when supported: live estimates use observed token growth; completed averages use output tokens divided by SDK-recorded request duration, including waiting. No timestamp-difference speed guesses, empty zero badges or added cost panels.

## Interface language
- The local interface defaults to English, including legacy browser preferences via a one-time locale-only migration. Later explicit language choices remain supported. Use Document, Pinned, New, Tasks and Sub-agents for English navigation.
- Translate system actions, loading/status text and accessibility labels through i18n; keep document names/content, conversation titles/messages, todo subjects/descriptions, agent task summaries and raw transcript/tool output unchanged. Never achieve English chrome by rewriting stored content.

## Native menu navigation
- `useMenuNavigation` installs the v1 fragment bridge only on the root Pi page after restoration. The document UUID and handled nonce set stay in memory, never shared storage. Exact protocol: [NavigationProtocol.md](../../../../pi-menubar/NavigationProtocol.md).
- Resolve existing sessions through the current catalogue or the authenticated same-origin summary GET, then reuse `handleSelectSession` with only its router replacement suppressed. Preserve draft/workspace/branch boundaries and same-session deduplication; never send prompts or approval responses through this bridge.
- Selection and history-state-preserving acknowledgement are synchronous. Ack binds the document, nonce and normalized target query; it means accepted selection, not completed transcript rendering. Explicit user navigation consumes any owned request already present, including queued hash events, before reannouncing ready; newer requests arriving afterward remain usable.
- Tests: `node --experimental-strip-types --test lib/menu-navigation.test.mjs lib/session-links.test.mjs`; on an isolated production candidate, `E2E_SERVER_MODE=start E2E_FOCUS=session-navigation node e2e/run.mjs` reuses the existing browser suite and its synthetic fixtures/cleanup.

## Shared read state
- Pi's running snapshot carries `sessionReadState` from `pi-web-session-read-state.json` in the existing agent directory. GET/POST `/api/sessions/read-state` shares it with the native menu; exact wire contract: [UnreadProtocol.md](../../../../pi-menubar/UnreadProtocol.md). Revisions and completion tokens persist under the existing cross-process lock/atomic-write helpers; corrupt, unreadable or regressed storage is unavailable, never reset to empty. Read tombstones block stale browser migration; session deletion removes records.
- Only the existing main-wrapper start and true-completion hooks write lifecycle state. Start clears old unread; aborted/suppressed/child runs do not generate completion tokens. Their synchronous enqueue order preserves start/end order, and polling never invents completions.
- `useSessionReadState`/`SessionReadClient` accepts monotonically newer snapshots, captures read tokens before queuing POSTs, and never retries a failed write automatically. Automatic reads require the active split conversation, a visible document, focus and a visible centre pane (neither desktop full-width nor an open mobile workspace). Explicit unread persists until attention changes or a newer completion arrives. A refused unread write suppresses only its previously observed token; a lost/invalid response conservatively preserves the first reconciled token, never every later completion. Each failed write produces fresh feedback; repeated poll failures deduplicate until a valid poll recovers. Archive/Undo and late Fork copies use the same requests.
- Browser-local unread is imported once per page only after a full catalogue filters out child/deleted IDs, using server tombstone guards, then removed on success; it is never rewritten from shared state. Summary catalogues cannot authorize migration, and catalogue filtering never prunes authoritative shared snapshots. Only a successful running response without the protocol field enables legacy behaviour. Network/auth/malformed responses preserve the last state. Runtime-scoped fetch/storage keeps Feynman on its existing legacy path; native legacy flags are never imported.
- Focused verification: `node --experimental-strip-types --test lib/session-read-*.test.mjs hooks/useSessionReadState.test.mjs lib/rpc-manager-shutdown.test.mjs lib/runtime-client.test.mjs`; isolated source browser check (no production build/model calls): `E2E_BROWSER_CHANNEL=chrome E2E_SERVER_MODE=dev E2E_FOCUS=read-state node e2e/run.mjs`.

## Right workspace
- Permanent Tasks, Sub-agents and Outputs tabs share the existing file/terminal workspace. They cannot be closed like documents. Mount their viewers only while the panel is open or previewed.
- A live Design Deck adds a session-scoped, non-closeable Design Deck tab and opens the right panel once. Reuse NativeBrowser (host-side Chrome, including remote clients); never open a desktop window/tab. Keep live deck viewers mounted across tab/session switches and panel collapse so selections and generate-more SSE survive. The existing running-session poll carries only live presentation records; do not recover capability URLs from saved messages or localStorage. Completion/abort/shutdown removes the tab. The package presenter adapter and activation boundary are in [design-deck.md](../design-deck.md).
- AgentWorkspace selection is local and read-only. Use a width-bounded custom dropdown, short display summaries, status and exact run/step IDs. Identical display summaries may group records visually, never merge their identities; unknown revival scaffolding must not imply common lineage. Keep keyboard navigation, Escape, outside dismiss and per-record access. Native conversations use SubagentViewer; package children use PackageSubagentChat. Never call a main-session selection handler, start an agent or redirect the composer from that picker.
- GET `/api/sessions/[id]/todos` reads the existing live manager or the saved current branch, never starts a wrapper or calls `todo`. The `rpiv-todo-state` custom snapshot is authoritative over legacy `todo` result details, including a cleared list. Hide deleted tasks, preserve pending/in-progress/completed and poll only the visible mounted view. These are the same tasks used by the tool, not a second task database.

## Search and conversation files
- Cmd/Ctrl+K conversation results reuse the sidebar's live running/awaiting-input sets and authoritative unread set through AppShell, without extra polling or storage. The right metadata slot uses the same icons and translated labels, with awaiting input taking precedence over running, then unread. Idle conversations, commands and file results have no activity icon; opening the menu alone never marks a conversation read.
- The sidebar search row contains only its search icon and editable input, with no visible Cmd/Ctrl+K button. Keep Cmd/Ctrl+K opening the quick-actions dialog through the global keyboard shortcut. Keep matching commands first, in stable order: new conversation, project terminal, conversation files, Rename this conversation, Fork this conversation, open its working folder in Finder. Recent conversations and actual conversation-body/file matches follow, with previews and exact message targets. Reuse the existing session-content search and guarded file-index endpoints, with debounced, abortable, query/cwd-bound results. Reuse the sidebar controller's disk-only Fork and existing loopback file-manager action, using the clicked conversation ID/cwd, not a different selected file-browser folder. Rename opens the sidebar's existing inline editor for the current saved native conversation (not a folded read-only subagent), clearing sidebar search and revealing the correct main/pinned/archive row without changing its archive or pin status. Enter/blur commits and Escape cancels through the existing rename flow. Fork uses the existing per-session deduplication, transient refusal and navigation-race handling; expose it only for saved native Pi sessions. Finder errors use the existing toast/body handling and reveal the sidebar on failure. Do not restore focus/sidebar/pin placeholders or add a long-conversation navigator.
- The IME, terminal and existing modal dialogs keep their shortcuts. Escape closes only the top modal and returns focus without stopping an agent; selection actions run after modal cleanup. Do not send model prompts from search.
- Outputs is a simple automatic file list, not a pin manager. GET `/api/sessions/[id]/outputs` reads the current/selected branch, including pre-compaction history, without starting an agent. Include successful write/edit paths (also SDK-recorded nested calls) and explicit assistant delivery links; deduplicate with the latest reference first. In the Outputs UI, stably prioritize reading material (documents, reports, slides, spreadsheets and images), then unclassified files, then engineering code/configuration/scripts; keep latest-reference order within each tier. Classification is a filename/extension heuristic, not a judgment of document content; do not change collection, truncation or access checks. Ignore read tools, user mentions, shell/stdout guesses, codemode store, arbitrary MCP text and full-output logs. Unreported shell-generated files and omitted/truncated nested arguments cannot be inferred; links are conversation file references, not proof of creation.
- Render file names and paths, with one-click FileViewer opening and the exact source session ID. Absolute paths outside cwd retain the existing session-reference/root/symlink checks; listing never grants file access. Do not scan directories, copy files, launch applications or consult project git state to infer ownership. A deleted or inaccessible file remains subject to the viewer's existing error handling.
- Only the visible mounted Outputs view fetches. Reuse the existing tool/run/focus refresh key, plus explicit refresh; no background polling or localStorage pins. During an active run, follow the manager's current leaf rather than freezing at the chat's earlier history snapshot. Abort superseded requests and isolate runtime/session/cwd/leaf scopes so stale responses never expose another conversation. Bound the response to the latest 500 paths and visibly disclose truncation.

## Chat attachments versus project uploads
- Manual `@` selection inserts the existing path; it never uploads or copies.
- Composer uploads/drops use POST `/api/chat-attachments`, storing non-image files under the agent's private `chat-attachments/<sha256>/<filename>` and inserting absolute references. Same content/name reuses its file; changed content never overwrites an earlier reference. Images retain their inline prompt path.
- Browser file upload cannot recover an original absolute local path; it must save a server-side attachment. Never claim this is an original-file link. The attachment store is not the session cwd, and composer uploads must not refresh/write the project explorer.
- Enforce bounded multipart input, 25MB/file and 100MB/selection, safe names, private file permissions and symlink refusal; clean only files/directories created by a failed call. The file explorer's explicit Upload action keeps its existing project-upload semantics.

## Voice input and Pi Live
- Native Pi main composers have realtime dictation (`gpt-live-transcribe`) and Live (`gpt-live-1`) controls; other runtimes and compact quote composers do not. The reply toolbar orders attachment, microphone and live waveform as separate 32px buttons with equal 12px gaps; keep the input surface and right-side model controls unchanged. The active chat model and image-model configuration are unchanged. Live requires an existing saved session.
- Dictation keeps the actual draft visible and editable while text arrives. Keep the left microphone/call icons and toolbar positions unchanged; no Waiting/Listening/Paused label, play/pause icon replacement, cancel/complete pair or popup. While preparing/listening, replace only the existing right-side send arrow with a two-bar pause control (enabled even for an empty draft), not a stop square; it pauses dictation, never sends/queues a prompt or aborts Pi work. Stop restores the original send arrow and retains the draft; clicking the unchanged microphone resumes. During active dictation, show the existing microphone-derived waveform in a noninteractive slot next to the editable draft, before the right pause control; never overlap transcript text or replace the draft. Hide it on pause/cancel, keep the left toolbar and pause position intact, and use the already-owned stream/analyser (no synthetic pulse or extra capture). Live still owns its separate inline capture row.
- Live uses the same inline composer row for status, elapsed time, microphone mute and hangup; subtitles/rates/usage stay under an on-demand details disclosure. Delegation confirmation remains an inline editable card, not a modal. Do not change the right-side model/theme controls or hide actionable errors and autoplay recovery.
- Dictation uses the official Realtime transcription-only WebSocket (`intent=transcription`, no model URL parameter), `session.update`, 24kHz mono PCM16 LE AudioWorklet, incremental transcript events and item-keyed final corrections. Reserve committed item order; reconcile separators after out-of-order completions and never overwrite an explicitly edited owned range. No response.create, assistant, Pi send/steer/queue or handoff. Only an explicit microphone click starts permission/media preparation and token/WS connection in parallel. Begin PCM capture as soon as media is ready, retain startup audio in a bounded local queue, and drain audio/commit events in order only after session.updated; use bounded socket backpressure and dispose queued audio on ownership loss. Startup is bounded at 20 seconds including media preparation. Connections are capped at 120 seconds, paused idle sockets close after 30 seconds, and resume reconnects if needed. Session/branch/rekey/send changes, split-pane ownership loss and pagehide cancel capture; late permissions/results cannot cross owners.
- `/api/voice/*` uses Web authentication plus explicit same-origin checks, fixed official OpenAI endpoints, server-only primary credentials, bounded bodies/rates and sanitized errors. Dictation reuses the existing official transcription credential only to mint a 60-second ephemeral client secret; the browser never receives the primary key or SDK headers. An unconfirmed socket close retains its bounded work hold. The legacy batch transcription endpoint remains for explicit diagnostic probes, not the dictation UI. Set `Accept: application/json` and `Accept-Encoding: identity`. Initialization waits return on abort, but keep unresolved-work blockers until the underlying promise actually settles.
- Live uses native WebRTC and `oai-events`, not Realtime events. Register listeners before the offer; complete ICE and await `session.started`. Show subtitles, elapsed/confirmed usage, local+upstream mic mute, autoplay recovery and the separate voice/backend costs. Use Safari 16.2-compatible cancellation with disposed listeners/timers.
- Delegation has no task text or utterance-complete boundary: show an editable confirmation card. Call/delegation IDs deduplicate admission; busy or changed branches refuse. Only the owned normal Pi prompt promise can provide a public final answer. Do not send thought/tool payloads, bypass trust/approvals, or retry an ambiguous submission.
- Hangup/ownership loss immediately stops microphone tracks, mutes output, restores the draft row and revokes pending/new server admission; remote close/usage confirmation drains in the background rather than occupying the capture surface. The 20-second connection deadline starts before ICE/upstream initialization, not after the start response; cancel aborts unfinished initialization. This remains independent of the bounded remote close/usage drain. Accepted Pi work continues. Admission expiry retains a conservative closure blocker; lost connections/final usage remain unknown. The local 20-minute cap is not a provider billing guarantee.
- Focused checks: `node --experimental-strip-types --test lib/voice-*.test.mjs lib/rpc-manager-voice.test.mjs`; `e2e/voice.mjs` checks draft-only input, confirmed/matched handoffs, cleanup and split ownership with synthetic media. Mocked browser success is not real-upstream or deployment evidence.

## Pending release handoff
- The footer adds only the localized Pending releases label and its count beside the unchanged Settings/Restart actions. It is an inline-size container: at 280px content width or less hide only the three text labels, retaining icons, the release count and full title/aria-label names; wider sidebars keep the text. Never clip overflowing labels to mask overlap. An independent desktop dialog shares Settings' shell, theme/font, focus and Escape tools, with pending/history views, evidence disclosures and copy-only handoff. Never fold it into Settings or Plugins.
- The shared registry covers completed, verified Pi Web/extension/memory/config work only. The default directory and CLI protocol live in [pending-releases.md](../pending-releases.md); `PI_PENDING_RELEASE_DIR` is a server/CLI environment override, never a request parameter.
- One UUID JSON per item; strict shared schema, no symlinks, per-ID cross-process lock, expected revision, exclusive create and atomic update. GET `/api/pending-releases` is read-only and no-store. Invalid items warn, directory failures are unavailable, and history does not count as pending. References are text only, never read from their target files.
- No automatic messages, main-Agent calls, release commands or service restart. Writers register only after completion/verification, then stop. Real registration and deployment require the operator's scoped authority. Never store credentials or real memory contents.

## Service restart
- ServiceRestartButton requires a confirmation dialog, waits for a changed server epoch and never resends an ambiguous POST. Manual AbortController/timeouts support Safari 16.2.
- POST `/api/service/restart` is only for same-origin loopback requests on 30141, the installed package cwd and the matching `cn.pi.web` launchd PID. Candidate/development instances reject it. No remote targets, arbitrary commands or force-busy overrides.
- Block running sessions, command admission/mutation waits, compaction, session creation, real extension work and live PTYs. Idle selected-browser leases are not work. Draining rejects new work and rechecks after asynchronous admission waits; Stop/control responses remain available.
- Implementation/testing does not authorize actually restarting the formal service. Unit/VM tests never run launchctl; candidate tests reject restart. A real restart still requires explicit operator confirmation and separate live verification.

## Pi Meta on macOS
- `/pi-meta` is a separate runtime using the existing title and command menus. Scope API calls, direct downloads, EventSource and deferred images through `runtimeApi`; only Web authentication and service control are shared. Sessions, settings, file roots and terminals are independent.
- The worker loads the verified original Pi 1.4.0 AgentSession, not the local interrupt patch. Its profile copies models/MCP settings once, shares the model account through the dual-lock preload, and retains the selected existing extensions and skill. MCP OAuth tokens remain separate.
- A private worker identity/socket and a dedicated macOS process group let Web adopt a surviving worker. A drained shutdown never signals unrelated processes and retains ownership while that group remains alive; a process that deliberately leaves the group is not covered by a Linux cgroup-equivalent guarantee.
- Manual restart drains Meta before the fixed launchd command. The external updater holds `/api/service/meta-deployment` open as a lease, rechecks busy state and commits the lease before stop. Disconnect releases only an uncommitted lease; a committed or ambiguous stop keeps admission closed until service death or explicitly proven cancellation. Unknown worker or lost lease blocks the stop; ordinary idle restart does not require manual cleanup.
- Prepare a release candidate's original SDK using `scripts/prepare-pi-meta-original.py` and the locally verified npm 1.4.0 archive. It refuses the live installation and existing unverified data. Revalidate the SDK fingerprint, account locking and release guard before activation; source checks do not authorize or prove deployment.

## Motion and file rows
- Quick Actions pages every result into groups of nine, with a 28px number column, flexible title, fixed 96px metadata column and 52px rows shared by commands and conversations. Every visible result has a 1–9 hint; left/right or PageUp/PageDown changes pages, up/down can cross pages. With an empty query, unmodified digits choose that row; with any query text (including a leading space), digits remain input and Alt/Option+1–9 chooses it via the physical `Digit` code. Keep matching `aria-keyshortcuts`, IME/repeat/browser-shortcut protection and the normal close/restore/run path.
- The top-bar in-session BranchNavigator uses its existing compact icon, not a persistent “Branches” label. Keep its title/accessible name, tree switcher and running-session lock; it is not the sidebar/Quick Actions Fork action that creates a new session.
- Micro feedback uses the shared 110ms workspace token; the quick-actions surface uses one 160ms opacity/small-translation entrance. Keep focus-visible feedback and selected theme/fonts; no looping decoration or transcript animation. Panel transitions share the workspace easing curve without extending the desktop's 200ms exit contract. Reduced motion disables panel, backdrop, composer and file-chevron transitions, including preview and inline-style overrides.
- File rows share 28px height and 6px corners. Preserve indentation, path tooltips, Git status, hover actions and folder expansion. Stacked file-header spacing does not change the files-tab layout or session navigation.
