# Pi 自动会话标题扩展

当前正式实现（2026-10-09）：独立 Pi 用户扩展，不修改 Pi Web 安装包。源码目录 `工具/pi-auto-title/`；加载入口 `~/.pi/agent/extensions/auto-title/index.ts`，通过目录软链接指向这里。Pi / Pi Web 普通更新不会替换用户扩展。

## 行为

- 按当前分支的真实用户消息数，在第 **1、5、10** 条消息结束事件各发起一次独立标题请求；不等待主回答结束、不阻塞主对话。输入尚未真正进入对话不计数，助手和工具消息不计数。
- 固定模型 `openai-codex/gpt-6-luna`，使用已保存的 Codex 登录；不跟随主对话模型，不自动换其他模型。
- 直接复用开源 Pi Web `lib/session-title.ts` 的标题提示词、对话提取/裁剪和结果清理。保留 MIT 版权声明，见 `LICENSE.pi-web`。这是独立实现，不依赖 Pi Web 内部 HTTP 接口。
- 第 10 条后的自动标题固定。手动改名（包括清空或改成相同文字）永久停止后续自动更新；原有、未标记归属的标题一律保留。
- 触发前同步保存一次尝试记录，刷新、重启、恢复会话不重复请求。某次失败不会循环重试；后续未触发的里程碑仍可执行。错误写入会话 custom entry，并在可用 UI 中提示。
- 第 1/5/10 条请求并发时，旧结果不能覆盖已保存的新里程碑标题。手动改名、关闭、重载或换会话使旧请求失效。
- 从当前分支读取消息；尝试次数、标题归属和手动停止记录按整个会话保存。切换分支不会重复消耗同一个里程碑。
- 子代理会话不命名。已有无标题会话可以在下一个尚未到达的里程碑命名，不补发错过的调用；已有标题不修改。

保存使用官方 `pi.setSessionName()`，元数据使用 `pi.appendEntry()`，不会把命名提示词、结果或状态放进主模型上下文。生成请求通过官方 `ctx.modelRegistry.streamSimple()` 调用，模型授权与网络由运行 Pi 的宿主处理。

## 安装与生效

```bash
ln -s /Users/guojiahang/Documents/pi/工具/pi-auto-title ~/.pi/agent/extensions/auto-title
```

新会话自动发现并加载扩展。已经加载的会话需要在空闲时执行 `/reload`，或重新打开会话使宿主重建扩展运行时。无需重启、重建 Pi Web。SDK 自定义宿主如果禁用了用户扩展，不会自动加载。

Pi Web 的标题以会话文件中的 `session_info` 为准。现有前端不专门处理扩展的 `session_info_changed` 事件；若后台生成在主回答结束后才完成，网页标题可能需刷新后显示。此扩展不为界面即时同步再次修改 Pi Web 资源。

更新 Pi 后只在其公开扩展接口发生不兼容变更时需要适配；不要再运行旧 title-guard 构建补丁。卸载：移除 `~/.pi/agent/extensions/auto-title` 这个软链接，保留本目录和现有会话标题。

## 验证

```bash
node --experimental-strip-types --test 工具/pi-auto-title/auto-title.test.mjs
node 工具/pi-auto-title/smoke-sdk.mjs
```

- 20 项针对性测试通过：1/5/10、重复事件、重载、清空/同名手动改名、生成中改名、磁盘侧改名、关闭/换会话、并发旧结果、错误、历史会话和子代理等。
- 使用 Pi 1.1.0 真实 SDK 的隔离会话验证通过。主对话模型被本地假回复替代，只有三次标题请求真实调用 `openai-codex/gpt-6-luna`。第 1/5/10 条分别保存标题，第 11～13 条不再请求，手动标题保护和 JSONL 持久化通过。
- `smoke-sdk-result.json` 保存真实标题与请求模型信息。脚本只创建临时隔离会话，完成后移除临时目录；重新执行会产生三次真实标题请求。
- 通过 Pi 官方扩展加载器加载成功，无加载错误；本机 Luna 模型与授权已确认。LSP 未报告源码诊断。

## 文件

- `index.ts`：固定模型、独立流请求、超时与结果清理。
- `core.ts`：事件计数、持久化去重、手动保护和生命周期。
- `title.ts`：Pi Web 的提示词、对话裁剪和标题清理。
- `auto-title.test.mjs`：离线针对性测试。
- `smoke-sdk.mjs`：真实 SDK 和 Luna 隔离验收。
