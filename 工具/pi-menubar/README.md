# Pi 菜单栏

原生 macOS 菜单栏入口：进行中、待审批、未读。普通 Web 会话切换到已打开的 Chrome Pi Web 标签；Web 标准审批和终端 `ask_user_question` 可在菜单里回答。

## 使用

- 黑白官方 Pi 图标；待审批时显示黄色小点，未读时显示黑白小点。
- 固定 280×454pt 纵向面板，内容超长时内部滚动；向右展开，靠近屏幕边缘时避让。原生玻璃、蓝底白字的选中和悬浮状态；少量青绿、橙、紫区分内容层次。禁用窗口阴影，并在圆角边界裁剪玻璃的外部 halo。
- 普通会话与“网页处理”复用 Chrome 已有的本机 Pi Web 标签：优先同一会话，其次已激活的 Pi 标签。展开菜单时仅在已有权限下预定位，点击先唤起窗口；新版页面通过 fragment 协议无刷新切换，收到同文档、同请求、同目标会话确认后，再按点击前捕获的完成版本提交已读确认；服务器快照确认后才清除未读。相同会话不写 URL；旧页面首次跨会话保留一次受限加载。找不到或操作失败只显示错误，不新开标签、不重发。首次显式点击可请求 Chrome 自动化权限。
- 顶部三个标签切换列表；进行中较少时，下方以细分隔线补少量“最近对话”，合计最多五条，运行中/待审批/子代理不混入历史，也不把历史计入进行中数字。Web 和终端待处理问答都会发系统通知，点击后进入对应的待审批条目。右键菜单栏图标可退出，退出不影响 Pi Web 或终端 Pi。
- 单选、确认、文本、多行编辑可原生处理。题干、选项标题/说明与底部操作分层；完整保留题目内容。`ask_user_question` 按当前 RPC 接口逐题显示：单选点击即发，自定义答案进入下一步输入；多选按题内说明输入，不伪造结构化复选框。显示层的推荐标识不改写提交的原始答案。自定义终端界面通过“网页处理”打开。
- 只接本机 `http://127.0.0.1:30141`；不修改 CodexBar、不注册开机启动、不安装依赖，日常使用不重启 Pi Web。无刷新桥的部署须单独获得当轮上线授权并走 Web 唯一守卫。`PI_MENUBAR_URL` 可指定其他本机 HTTP 端口。

## 构建与验证

Apple Silicon / macOS 14+，使用系统 Swift，无包依赖。

```sh
bash test.sh
bash test.sh --tui     # 另加隔离的真实终端 Pi 与已安装 ask_user_question，无模型请求
bash test.sh --live    # 只读 API；有待审批会话时核对 SSE 快照
bash test.sh --render  # 原生列表和合成审批截图，保存在忽略的 build/ 中
bash build.sh 'build/Pi Menu Bar.next.app'
# 已授权后的真实 Chrome 只读诊断：不创建菜单、不切页/激活，也不弹权限请求
open -W -n -g --stderr "$PWD/build/browser-native-check.log" \
  'build/Pi Menu Bar.next.app' --args --check-browser
# 已授权的现有 Pi 窗口唤起计时；不改 URL、不新开页、不询问新权限
open -W -n -g --stderr "$PWD/build/browser-warm-focus.log" \
  'build/Pi Menu Bar.next.app' --args --focus-existing --prewarm
```

运行中不覆盖当前 bundle；验证后只退出此应用，再替换 `build/Pi Menu Bar.app`。启动：`open 'build/Pi Menu Bar.app'`。首次允许通知。首次网页跳转需允许“Pi Menu Bar 控制 Google Chrome”；若拒绝，可在系统设置 → 隐私与安全性 → 自动化中自行调整。

源码在 `Sources/`，测试在 `Tests/`，构建与缓存留在忽略的 `build/`。图标原件 `Resources/pi-logo.svg` 来自 [pi.dev/logo-auto.svg](https://pi.dev/logo-auto.svg)，保留原形状并渲染为系统黑白模板。macOS 26+ 使用 `NSGlassEffectView`，旧系统回退原生材质。

## 终端问答

- 终端桥 `TerminalBridge/index.ts` 需单独加载到交互式终端 Pi；Web/RPC 不启用此桥。更新菜单栏及安装全局桥接须单独确认，已有终端会话需在合适时机 `/reload` 或新开会话；正在等待的问题不会追溯重建。
- 使用 `ask_user_question` 的公开事件及外部答复接口，支持单选、多题、多选和自定义文字；题目含富预览或内容过长无法完整同步时只提示回终端处理。其他类型的原生终端对话框不在覆盖范围内；单个终端最多追踪 32 个并发问答。
- 终端通过仅当前用户可访问的 Unix socket 连接；桥接层的题目和答案只在内存和连接中传递，不额外落盘，Pi 会话仍按自身机制保存。按用户选择，不做配对或进程身份验证：私有目录和 socket 只隔离其他账户，**同一账户的其他进程仍可伪造问题、读取或提交回答**；仅在信任该账户程序的环境使用。
- 多端首个有效回答生效。菜单栏只在明确点击后发送；断线保留禁用的失联提醒，不自动重发，重连后以终端快照为准。通知按实例和问答去重，终端实际结束问答后清除；可以手动移除失联提醒，该操作不回答终端问题。

## 状态与审批边界

- 未读与 Web 共用服务器状态：网页读过后，菜单随现有约 2.5 秒轮询自动同步；菜单成功打开会话后也向同一状态确认已读。确认绑定点击前的完成版本，不会清掉等待期间新完成的内容。只在旧 Web 不支持该协议时保留原有本地行为；网络/认证失败不会伪造清空或自动重发。旧原生未读不导入服务器；协议见 [UnreadProtocol.md](UnreadProtocol.md)。
- Chrome 控制只读取定位所需的 URL/ID/index 元数据，不读取页面正文或浏览器凭据，不执行 AppleScript、JS 或键鼠自动化。短期缓存绑定 Chrome PID，8 秒失效；预定位不持续扫描。协议见 [NavigationProtocol.md](NavigationProtocol.md)，网页桥是随前端部署的逻辑，不是原生注入脚本。每次修改带执行时求值的目标 ID＋原 URL 条件；标签被重排、页面变化或 Chrome 不支持条件时停止，不退回无条件写入。注入测试不代表真实 Chrome 兼容性验收，首次使用仍需确认系统权限并检查原标签复用。
- 审批通知按会话＋请求去重。提交捕获 endpoint、sessionId、UI id；同步锁住后再发送，确认和取消共用锁。断线、休眠和超时禁用旧题，重连必须重新获得快照与题目详情。
- 答案不自动重发。连接中断、服务错误或未知响应显示“发送结果未确认”；HTTP 200 仅说明接口返回，不证明本客户端答案赢过网页等其他客户端。结束事件只关闭题目。
- 网络限本机同源；POST 拒绝重定向。原生层只读取自身 WebKit 中适用的 Pi 认证 cookie。密码保护下若收到 401/403，交网页处理；浏览器登录不会自动给原生应用登录。不读取其他浏览器凭据或 Pi 模型密钥。
- Tailscale 图标隐藏需在系统设置 → 菜单栏中关闭显示，不要退出或断开 VPN。Pi 与 CodexBar 的顺序若系统未提供公开设置，可按住 ⌘ 拖动菜单栏图标调整；本应用不改写未知系统位置数据。
