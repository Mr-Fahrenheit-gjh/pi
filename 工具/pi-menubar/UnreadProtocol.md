# Pi Web / 菜单栏共享未读合同 v1

服务器保存唯一已读/未读状态；客户端本地存储只用于旧版兼容，不覆盖已经确认的共享状态。仅通知状态变化，不发送提示词或审批答案。

## 快照与操作

- 既有 `GET /api/agent/running` 新增可选 `sessionReadState: { revision, unread }`。`revision` 是持久化、非负安全整数；`unread` 是 session ID → 正安全整数 token 的映射。
- `GET /api/sessions/read-state` 返回 `{ state: { revision, unread } }`。失败不能伪装成空状态。
- `POST /api/sessions/read-state`，JSON：
  - `{ action: "read", entries: [{ id, token }] }`：只清除当前 token 对应的未读；迟到的旧 token 不清除新完成。token=0 仅确认当前没有未读的会话，不能清除任何已存在的未读。
  - `{ action: "unread", ids: [...] }`：显式标为未读；已未读时幂等，不生成另一完成事件。
  - `{ action: "import", ids: [...] }`：浏览器旧未读的迁移，仅接纳服务器从未记录过的 ID。已读记录也须留存以拒绝陈旧迁移；原生不导入其独立旧标记。
- POST 成功同样返回 `{ state: { revision, unread } }`；校验同源、认证、JSON类型、ID/token和请求大小。每请求最多500个唯一ID，ID不超过200字符，沿既有安全ID规则；拒绝未知字段及非法结构。全部响应禁止缓存。
- read 批次的 token 必须来自用户选择时或确认前已观察到的快照，不能在异步操作结束后换成更新的 token。失败不自动重发，保留未读并显示可理解的同步错误。

## 服务端

- 原子持久化与跨请求串行/锁保护；快照版本单调。GET仅读取，不凭某客户端的轮询制造完成事件。
- 原有真正的主代理运行完成接点生成新未读 token；停止/被抑制通知/只读孩子不生成。开始新运行清除旧未读；同一次运行的重复结束不生成重复 token。
- 记录分为未读与已读墓碑；迁移不得覆盖已经读过或新完成的记录。删除会话时清理其记录，不能让未知/坏存储被悄悄重置为空。

## 网页

- 成功收到共享快照后，以其为唯一来源，不再从 running 集合变化独立追加/持久化未读。后台完成提醒仍沿原有逻辑。
- 自动已读限当前真正可见且聚焦的会话；会话选择、页面重新可见/聚焦、新完成快照到达均重新核对。隐藏或后台标签不得清除未读。保留分屏活动会话边界。
- 显式标为已读/未读、归档/撤销与Fork副本的既有语义通过同一接口实现。较旧GET/POST响应不得覆盖更新快照。
- 旧浏览器localStorage未读只作上述安全迁移；服务端不支持共享协议时保留旧行为。网络/认证失败不是“不支持”，不能回退后覆盖共享状态。

## 原生

- 每次现有轮询读取共享快照；成功后丢弃独立推导，网页读过后下一次轮询自动消除，无需菜单再点一次。
- 只在原生导航成功/同文档ack确认后发送read；只清除导航开始时捕获的token，不清除等待期间新完成的内容。收到成功快照才更新本地状态，拒绝倒退的revision。
- 无协议字段兼容旧Web；坏字段、断线或401/403保留最近有效状态，不伪造清空。POST限已配置的本机同源且不跟随重定向，不读取浏览器凭据。

## 最小回归

双向已读、跨标签、后台页不误清、新完成晚于旧read、旧迁移不能复活已读、断线/重连和进程重启持久化、停止与孩子抑制、旧后端兼容，以及原有审批和无刷新导航边界。
