# pi-menubar 项目规则

- 使用系统 Swift / AppKit / SwiftUI / WebKit / UserNotifications；无包依赖。日常改动不修改或重启 Pi Web；无刷新桥须遵守 NavigationProtocol.md，并有当轮明确授权后沿 pi-web-maintenance 唯一守卫上线。
- 普通会话复用已打开的 Chrome 本机 Pi Web 标签，不新开、不嵌入网页。用户已授权应用直接使用 Chrome 原生 Apple Events；只查 URL/ID/index 定位目标，不运行 AppleScript、JS、键鼠自动化或读取浏览器 profile。首次控制权限由用户在系统提示中确认；无目标、权限拒绝或条件不支持时停止，不另开浏览器兜底。写入使用执行时求值的 ID＋原 URL 条件，不能退回无条件写入。
- Web 审批用现有 SSE + `extension_ui_response`，只在用户明确点击后提交原始答案；不猜测问卷结构、不模拟按键、不自动批准、不重试写入。
- 终端只覆盖 `ask_user_question` 的公开事件；按终端实例、会话、toolCallId 和连接代次锁定，接收方按原问答协议确认结果。富预览、无法完整同步的题目必须回终端处理。用户选择不配对、不做进程身份验证，信任本机同一账户；私有 Unix socket 仅隔离其他账户，同账户进程仍可冒充或作答。断线保留禁用状态并等待快照，通知按问题去重；不修改正在运行的 app 或自动安装全局扩展。
- 原生支持 select / confirm / input / editor；custom 交网页处理。当前 RPC 多选是带说明的 input，不从标题反推复选框。按 endpoint＋sessionId＋UI id 锁定答案，断线/休眠/过期禁用，重连先快照后重放。HTTP 200 和关闭事件不等于本客户端答案已生效。
- 所有网络入口限本机同源；POST 不跟随任何重定向。仅可读取本应用自身、路径适用且未过期的 `pi_web_session` cookie，不读取其他浏览器 cookie 或 Pi 凭据。401/403 暂停原生审批并交网页处理，不声称浏览器登录会修复原生登录。
- 未读以 Web 共享状态为准（UnreadProtocol.md），按完成 token 确认已读，旧请求不可清除新完成；网页读过后由既有轮询同步。原生旧标记不导入服务器，只有未宣告共享协议的旧 Web 才保留本地推导。网络/认证/格式错误不能当成空快照或旧协议，不自动重发写入。离线不能被解释为任务完成；仅打开审批或隐藏面板不算阅读完成的会话。
- 品牌图标用 Pi 官方 https://pi.dev/logo-auto.svg 的原形状、系统黑白模板。待审批在旁边叠加独立黄色小点，未读用黑白点；菜单栏不放数字、三角形。
- 面板固定 280×454pt（约 1:1.62），保留纵向轮廓，内容超过后内部滚动，不因只有一条会话缩成横条；向右展开，屏幕边缘才避让。禁用窗口阴影并裁剪玻璃自身外部 halo；必须结合真实显示核验，不能只看 hasShadow。
- 简洁、克制、优雅、美观、方便、有功能：三类状态单选标签即可，不加重复品牌栏、冗余分组标题、搜索和更多菜单。用户允许在进行中较少时补充“最近对话”：细分隔线区分历史，不混入运行中、待审批或子代理，不计入进行中数量，合计最多补到五条。选中与 hover 用系统蓝底白字；非选中状态以青绿、橙、紫作少量内容强调，不把全部内容染成蓝色。审批题干、选项必须完整可读。玻璃用 NSGlassEffectView，旧系统回退原生材质。
- Chrome 脚本读写事件使用 `kAECoreSuite`（`core`），不是 `kCoreEventClass`（`aevt`）；注入测试须独立校验事件字面值。预定位缓存仅保留 Pi URL/ID/index，绑定 PID 和短期 TTL；命中仍校验执行时条件。先唤起再发同文档 fragment 请求，ack 必须绑定 page/nonce/query 目标；未确认不得提交已读、重发或降级重载。导航前捕获 read token；收到服务器已读快照才清除，不以导航 ack 冒充已读写入成功。`--check-browser` 是原生只读诊断：已有授权下查定位元数据和条件匹配，不询问新权限、不切页、不激活、不创建菜单实例，不输出 URL/ID。
- 构建产物留在 build/；最小验证 `bash test.sh`。`--live` 仅检查本机只读 API，`--render` 只读刷新列表并渲染原生菜单与合成问题，不发送真实提示词或审批答案。
