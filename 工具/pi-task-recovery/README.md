# Pi 共用任务恢复（阶段实现）

版本：本地 0.1.0；适配 Pi 核心 **1.2.0**。不是替换为实验性的 pi-durable；借鉴它的持久检查点、恢复次数与不盲目重放原则。

## 当前已实现

- 全局 `~/.pi/agent/settings.json` 使用原生网络重试：原请求失败后最多重试三次，间隔 15、30、60 秒。provider 内层重试保持 0，避免多层次数相乘。
- 全局扩展 `~/.pi/agent/extensions/task-recovery` 链接到本目录，适用于终端、Web 和加载个人扩展的原生子会话，不只在 Web 前端生效。
- 在原会话 JSONL 的当前分支记录小型 `pi-durable-task` 检查点，不另存任务正文或凭据。
- 新进程重新打开该会话时，未结算且安全的模型工作在 15 秒后恢复。原输入不重新提交，已有工具结果保留。
- 原生网络重试与重启恢复共用持久次数。进程重启不重置失败次数；实际模型成功进展才重置连续失败计数。
- 三次失败后暂停，并写入可见的会话说明，不让它被当成完成。
- 共用 `AgentSession.abort()` 在取消等待前写入停止记录，覆盖终端 Escape、Web Stop 和原生调用方 abort；等候恢复时按 Stop 也有效。
- 最终答案已提交时不再生成一次；fork 不继承原会话恢复权；旧拥有者进程仍活着时不启动第二个恢复者。
- 中断时有尚未核实的工具调用或等待用户确认时暂停，不自动重放写入、发布、删除或子代理启动。恢复不能增加原任务授权。

## 尚未完成，不能宣称全量上线

1. 当前运行中的宿主仍缓存旧核心，需要空闲后重新启动；终端需新进程，Web需安全重启。`/reload` 可重读设置与扩展，但不足以加载已缓存的核心补丁。
2. 该实现是**重新打开原会话后的自动恢复**，不是自动重新启动关闭的终端、机器或已退出的进程。
3. Web 目前仍按访问惰性打开会话。没有启动扫描协调器，因此服务重启后没人打开的旧会话不会自动执行。完整无人值守恢复还需共用持久索引与各宿主接入。
4. 原生子代理可共用网络重试与检查点；失败子代理的自动重新调度尚未接入 pi-subagents 的正式 resume 协议。不得用普通 Pi CLI 或交互 shell 绕过原工具、权限、工作区和调用次数契约。
5. 老会话之前没有本扩展检查点，不能推断其任务应恢复。不会批量唤醒历史任务。
6. 保存到 JSONL 不等于断电时每次写入已同步到物理磁盘；本轮验证覆盖进程 SIGKILL，不宣称实现完整数据库事务或工具 exactly-once。

## 安装和验证

```bash
node 工具/pi-task-recovery/install.mjs
node --test 工具/pi-task-recovery/engine.test.mjs 工具/pi-task-recovery/integration.test.mjs
```

安装器只接受 1.2.0，先验证全部补丁匹配再修改。对全局 CLI 安装与 Web 内置安装，分别补 `dist/core/agent-session.js` 和实际 bundled AgentSession chunk。只增加三个共用接点：Stop 持久记录、读恢复次数、重试前保存次数。没有修改 Web UI、构建产物界面、模型、凭据或子代理调度协议。

原文件备份在 `~/.pi/backups/pi-task-recovery-1.2.0/`（本机私有，不入库）；安装器只更新 settings 中 retry 对象，不将全量用户设置写进 Git。Pi 升级后先检查新版本支持情况，不能盲目套用此补丁。

验证记录：`validation.json`。18 项测试通过，含两套核心的普通 SDK 与打包 SDK 入口、每套核心的真实子进程 SIGKILL 后磁盘重开恢复。测试提供假模型流，不调用模型服务、不读取用户凭据；故障测试会创建并清理临时目录。

`/recovery-status` 查看当前会话的检查点状态。

设计依据：<https://github.com/earendil-works/pi/tree/main/packages/durable>。
