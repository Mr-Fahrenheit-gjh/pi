# 工作区约定

适用于使用者选择的工作区及子目录；子目录独立仓库在其内部提交。

## 常驻边界

- 全局安装或升级、brew、launchctl 配置变更、sudo、shell/系统配置，必须先确认。版本升级与依赖新增、升级、删除也须先确认。
- 只做批准范围内的改动，不顺手重构。默认只在工作目录内写入；用户明确指定的外部配置文件除外。临时文件放 `/tmp` 或任务目录，结束时清理自己的临时产物和进程，不删除用途不明的文件。
- 浏览器操作遵守 `browser-harness` 技能：默认独立无头浏览器；允许经 OpenCLI 扩展操作任务相关的现有标签页。不使用桌面按键自动化或日常 profile 的远程调试连接。
- 交付前运行最小相关验证，给出命令与结果；未验证或受阻就明确说明，不把未完成任务说成完成。

## 执行分寸

- 工程任务先查现成能力：项目已有设置、命令、API、组件或脚本能解决，就直接给操作，不新写实现。
- 默认做到够用为止：小改动不建流程，不为一次改动写计划、独立审查或全套验收矩阵；先跑能发现本次错误的检查，通过即停。
- 完整构建与正式验收按交付目标需要执行；多个小改动默认批量发布。
- 验证失败先判断是产品问题还是验收设施问题；只修验收脚本时不重建产品，不重跑已通过的全套检查。

## Git

- 开始检查状态，区分既有积压和本任务改动。验证后默认每项任务做一次本地提交，只暂存相关文件，不用 `git add .`；不覆盖他人暂存、不擅自回滚、改写历史或推送。
- 凭据、私密运行数据、`系统数据/`、缓存、构建产物不入库；不为清空状态批量提交或删除积压。未完成的阶段提交须明确标记；提交受阻则说明原因。
- 获准的版本/依赖变更应一起提交源码、版本声明、锁文件和必要维护记录，版本提交写明版本。交付简短给出提交标识和相关未提交项。
