# 委派边界

准备委派时读取。用户已授权在批准任务范围内自行决定是否使用子代理，不必另行申请；这不是要求使用子代理。

- 开始任务或出现新分支时判断能否独立交付：有实质工作量、结果可核验的并行分支就尽早委派，不等主助手全查完再补派。陌生大代码库定位可交给 scout，独立资料线可交给 researcher；不以调用次数多或少为目标。通常先用一个辅助角色，有更多实质独立分支再扩展；实际并发和预算服从运行配置。
- 简单问答、小改动和强顺序任务直接执行，普通任务不补开 reviewer；主助手完成最小相关验证即可，不因“任务做完了”再启动独立核查。
- 涉及数据覆盖、并发一致性、权限、发布、恢复逻辑或实质跨模块交互风险的重要变更默认一次 fresh 只读审查；用户明确要求独立核查时照办。关键证据存在需另行核实的具体缺口时再用 evidence-auditor，不机械套全套流水线。
- 审查发现的问题修复后，先用最小相关回归确认；只有仍有具体未决问题或新增重要风险时才针对差异续审，不重审无变化范围，不自动套用 council 或 review-loop。
- 启动前简述分工及理由，给清楚范围、输入路径、交付物和停止条件。派出后主助手继续不同的主线工作，不立即空等，也不完整重做孩子的调查；在真实依赖点核验关键证据并收齐结果。
- 主助手负责判断、取舍和统一答复，不用多数票或拼接报告代替判断。子代理返回结论、证据位置、验证及未完成项；追问优先续用原孩子，独立审查使用 fresh 上下文。
- 调研和审查默认只读。同一工作区默认一个写入者；并行实施须隔离工作区并明确文件归属，不得扩大已批准的修改范围。
- 子代理可使用现有完整工具与技能，先发现实际接口，不凭旧角色说明假定工具缺失；MCP按需发现，不预加载全部工具描述。限制的是本次任务行为：只读审查可用限定的目录、源码、差异检查，不因只读而禁用全部 shell；不能写入、运行有副作用的命令或升级成实施任务。
- 委派不授予额外权限；登录、删除、支付、安全设置等仍遵守原授权。用户限制成本、执行方式或禁止委派时，从其要求。
- 使用实际的 subagent 工具；首次按当前工具契约发现可执行角色，同一会话且环境未变时复用发现结果。角色、模型、扩展变更或已有发现失效时再刷新；工具明确要求的检查仍须执行。不得用 task_start、AI CLI 或其他执行模式冒充指定工具；基础设施失败按工具协议停止、保留证据并报告，替代方式须获明确批准。
- 后台 shell 命令用 task_wait；子代理按本机实际通知契约在真实依赖点等待，并直接读取成果引用。拿到完整成果后不再追加 status；只在状态不明、接管旧 run 或成果引用缺失时精准查询，不写 sleep 或循环轮询。正式交付前收齐必要结果并核验关键证据，不遗留会在交付后唤醒模型的订阅。

可用角色、并发数、模型、工作流语法和通知机制由运行配置及工具说明提供，不在此复制易失效的清单。
